# Plan: Judging style guide panels announced as dialogs to screen readers

**File:** planning/2026-10-14-judging-style-guide-dialog.md
**Goal:** The two bottom sheets on the judging screen (section guideline, style info) are real modal dialogs for assistive tech: role, accessible name, focus in on open, focus back on close, Escape closes, Tab stays inside.
**Out of scope:** Marking the rest of the page `inert`/`aria-hidden` while a sheet is open (`aria-modal="true"` plus a Tab wrap covers it); adding `@alpinejs/focus` or any other dependency (hand-rolled, about 20 lines); changing sheet layout, transitions or content; other walkthrough findings in `docs/user-journeys.md`.
**Constraints:** Shared wave rules 2026-10-14: new user-facing strings are Blade-injected `judging.*` lang strings, added to BOTH `lang/en.json` and `lang/nl.json` in the same commit (TASK-107's parity test, once it lands, fails otherwise); no JS string literals for user-facing text. Runs after TASK-84, which edits the same `resources/js/judging.js` and `resources/views/judging/show.blade.php`; this plan assumes TASK-84 has landed and rebases on it. CLAUDE.md Playwright rules apply: `getByRole`/`getByTestId`, never Tailwind classes or `filter({hasText})`.

## Phase 1: TASK-90, dialog semantics and focus handling on both sheets (Low)

**Outcome:** Opening either sheet makes a screen reader announce a named dialog and puts keyboard focus on it; Escape, the close button or the backdrop closes it and returns focus to the control that opened it; Tab cannot leave it. Names are localised (en, nl).

**Scope decision (stated, not asked):** TASK-90 says "the panel", the walkthrough says "the style guide panel". The screen has two sheets with identical markup and the same defect: the section guideline sheet (`styleGuide`, `data-testid="style-guide-panel"`) and the style info sheet (`styleInfo`, `data-testid="style-info-panel"`). Fixing one would leave the other announcing nothing, so both get the same treatment (parity). Revisit if Oscar wants only the first.

**Design sketch:**
- Each sheet's inner panel (`style-guide-panel`, `style-info-panel`) gets `role="dialog"`, `aria-modal="true"`, `tabindex="-1"` (programmatic focus target, so the dialog and its name are announced on open), and a name:
  - guide sheet: `:aria-label="styleGuide.label"`, built in `openGuide` from a Blade-injected template `labels.guideDialog` (`judging.aria.guide_dialog`: en "Guideline for :section, :style", nl "Richtlijn voor :section, :style"). `:section` is the lowercased section name, taken from the same Blade-built, `mb_strtolower`ed value as the existing `labels.guide` templates (not `labels.sections`, which is capitalised), so the en name is e.g. "Guideline for appearance, American IPA". Same `.replace(':x', () => v)` pattern as `guideLabel`.
  - info sheet: `aria-labelledby` pointing at the existing heading `<div>` (`styleCode · styleName`), which gets an `id`. No new string.
- Backdrop `<div class="absolute inset-0 bg-black/40">` gets `aria-hidden="true"`.
- The `×` close buttons get `aria-label="{{ __('judging.aria.close') }}"` (en "Close", nl "Sluiten") and the glyph is `aria-hidden`. Today they are announced as "times". Side effect: the accessible name changes from "×" to "Close", so the six `getByRole('button', { name: '×' })` locators in `tests/Browser/judging-style-guide-srm.spec.ts` (lines 60, 82, 118, 177, 188, 218; red-team confirmed) must change to scope `getByRole('dialog').getByRole('button', { name: 'Close' })`. The same task edits that file.
- The scroll regions (`style-guide-scroll`, `style-info-scroll`) get `tabindex="0"` so keyboard users can scroll them; they are the second Tab stop after the close button.
- Focus in: on open, remember the trigger (`$el` passed from the click handler as an extra argument; fall back to `document.activeElement`, because Safari does not focus buttons on click), then focus the panel after `$nextTick` AND a `requestAnimationFrame`: `$nextTick(() => requestAnimationFrame(() => panel.focus()))`. Red-team probe (Alpine 3.15.12): `x-show` without its own transition applies `display` in a `requestAnimationFrame`, `$nextTick` runs via `setTimeout`, so plain `$nextTick` focus lost the race in 28 of 40 programmatic opens and won 5 of 5 with the rAF variant. Trigger kept in a closure variable inside `judgingApp`, not in Alpine reactive state.
- Focus out: `closeGuide`/`closeStyleInfo` (close button, backdrop, Escape) restore focus to the remembered trigger if it is still connected, then clear it. Both closers return immediately when their sheet is not open. Required: both sheets listen with `@keydown.escape.window` (show.blade.php), so the closers run on every Escape on the page; without the guard, Escape typed in a notes textarea after any earlier open/close moved focus to the old trigger (red-team probe). Change the two `@keydown.escape.window` handlers to `styleGuide.open && closeGuide()` / `styleInfo.open && closeStyleInfo()` as well.
- Tab trap: `@keydown.tab` on the panel calls one shared `trapTab(event, panel)` that wraps Tab from the last focusable to the first and Shift+Tab from the first (or the panel itself) to the last. Focusables are `button, [tabindex="0"]` inside the panel.
- The five `openGuide(entry.id, '<section>')` call sites (show.blade.php ~258, 281, 304, 327, 350) and the two `openStyleInfo(entry.id)` call sites (~174 click, ~175 Enter keydown; red-team verified the count) pass `$el`.
